## Этап 1. Единая точка конфигурации рантайма (`config.py`)

Цель: устранить Б11, Б13, Б19 (дубли `async_ping_ip`, «привязка» модулей к старому `sem`, приватный `sem._value`).

1. **Убрать дубль пинга:** оставить только `config.async_ping_ip`, но внутри обращаться к семафору через модуль, а не глобальную ссылку:
   ```python
   async def async_ping_ip(ip: str) -> bool:
       async with sem_ref():          # функция-геттер, возвращает config.sem
           ...
   ```
   Проще и надёжнее — инкапсулировать семафор в класс-обёртку:
   ```python
   class PingThrottle:
       def __init__(self, limit): self.limit = limit; self._sem = asyncio.Semaphore(limit)
       def resize(self, new_limit):
           self.limit = new_limit
           delta = new_limit - self._sem._value  # или пересоздать, см. ниже
           self._sem = asyncio.Semaphore(new_limit) if no active else ...
       def free(self) -> int: ...
       async def acquire()/release() через contextmanager
   throttle = PingThrottle(MAX_CONCURRENT_PINGS)
   ```
   Все модули импортируют **не `sem`, а `config` / `throttle`** (`from config import throttle` — объект мутируемый, ссылка не «протухает»). Тогда админское изменение лимита действительно применяется мгновенно. Пересоздание `Semaphore` допустимо, т.к. изменение лимита — редкая операция; активные `async with` доработают на старом объекте без утечки (Python GC), новые пинги возьмут новый.
2. **Свойства вместо привата:** `throttle.free()` и `throttle.busy()` вместо `sem._value` во всех местах (`start.py:33`, `admin.py:44,88,103`).
3. **Валидация IP centrally (Б4):**
   ```python
   import ipaddress
   def is_valid_ip(s: str) -> bool:
       try: ipaddress.IPv4Address(s); return True
       except ValueError: return False
   def is_valid_subnet(s: str) -> bool:   # x.x.x.0, октеты 0..255, НЕ x.x.0.0
       ...
   ```
4. **Пер-юзерские файлы результатов (Б18):** убрать общий `RESULT_FILE`; функция `result_path(user_id) -> f"results/result_{user_id}.txt"` + создание каталога в `init_files()`.
5. **ALERT_CHAT_ID (Б20):** при невалидном значении — `print` предупреждение и `ALERT_CHAT_ID = None` (не оставлять строку).
6. Проверка: `python -c "import config, handlers.scan, handlers.admin, handlers.monitor, handlers.start, handlers.tree"` без ошибок; unit-тесты `is_valid_*` на `256.1.1.1`, `999.999.999.5`, `1.2.3.4`, `66.86.15.0`, `1.2.0.0`.

2. **Crash-guard всего цикла (Б10/Б22):** тело `while True` обернуть в `try/except Exception as e: print(...)` — ошибка одного пользователя/часа не должна останавливать задачу. В `main.py` добавить respawn:
   ```python
   async def monitor_supervisor():
       while True:
           try: await hourly_monitor_loop()
           except asyncio.CancelledError: raise
           except Exception as e: print(f"Монитор упал: {e}"); await asyncio.sleep(60)
   asyncio.create_task(monitor_supervisor())

   ```

6. Проверка (unit, без Telegram): мок `bot.send_message`, данные вида `{"111": ["8.8.8.8","10.255.255.1"]}` → алерт формируется без исключения, текст содержит тег `tg://user?id=111`, gather завершается быстрее суммы таймаутов.

## Этап 3. Сканирование (`handlers/scan.py`)

1. **Удалить локальный дубль `async_ping_ip`** (строки 12–24) → `from config import async_ping_ip, throttle, is_valid_ip, is_valid_subnet, result_path_for_user`.
2. **Валидация целей (Б4, Б3):**
   - каждый одиночный IP → `is_valid_ip`; каждая подсеть (`x.x.x.0`) → `is_valid_subnet` (октеты ≤255, запрет `x.x.0.0`);

3. **Прогресс в реальном времени (Б5):** перейти от чанков `total//4` к потоковой обработке:
   ```python
   pending = {asyncio.create_task(async_ping_ip(ip)): ip for ip in all_ips}
   done_cnt = alive_cnt = 0
   throttle_updates = asyncio.Lock()/last_update_time
   for coro in asyncio.as_completed(list(pending)):
       alive = await coro; done_cnt += 1; alive_cnt += alive
       if time.monotonic() - last_update >= 1.0 or done_cnt == total:  # edit-троттлинг ~1 Гц
           await update_progress(...)   # wrap в try/except TelegramRetryAfter/CantParse
   ```
   Это даёт непрерывный прогресс и устраняет «рывки» ожидания самого медленного пинга в чанке. Ограничение частоты редактирования (~1 раз/сек) обязателен против flood-limit Telegram (Edit 20/мин в чат — держать запас).
4. **Обработка ошибок редактирования (Б17):** все `edit_text` в `try/except TelegramAPIError`; при провале — печатать прогресс не критично, финальный результат дублировать новым сообщением (не editing).
5. **HTML-экранирование (Б17):** `html.escape(display_target)` перед вставкой в parse_mode=HTML (цели приходят от пользователя).
6. **Группировка истории (Б9, Б3):**
   - сохранять отдельными типами записей: `"type": "subnet"` (скан `x.x.x.0`, total=256) и `"type": "host"` (одиночные IP, total=1); не превращать одиночные IP в псевдо-подсети;
   - запрещённые `x.x.0.0` не должны попадать в историю даже через одиночные IP: узел `x.x.0.y` сохранять как host, но в `/tree` помечать сеть-префикс как «запрещённая зона» либо не агрегировать вовсе — согласовать с ТЗ: блокировка касается именно запуска скана подсети;
   - добавить `scanned_by` (user_id) и накапливать историю измерений (append записи, а не перезапись той же сети) — при этом `/tree` показывает последний срез; ограничение размера истории (напр. 500 последних записей + dedupe по target).
7. **Пер-юзерский `result.txt` (Б18):** писать в `result_path_for_user(user_id)`, отправлять `FSInputFile(path, filename="result.txt")`; удаление файла после отправки или overwrite при следующем скане того же юзера.
8. **Надёжность `active_users` (Б6):** заменить `set` на `dict[user_id, task_started_ts]` + проверка stale (если запись старше N минут без активности — считывать как мусорную и чистить); освобождение строго в `finally` (уже есть) + обёртка всей логики скана в `try/except` с сообщением пользователю об ошибке вместо зависшего «⏳».
9. Проверка: тест-скан `8.8.8.8 1.1.1.1` (несколько обновлений прогресса >4), `/scan 999.1.1.1` → понятная ошибка; параллельные сканы двух юзеров → разные файлы отчётов; `/tree` после одиночных IP показывает hosts, а не фейковые подсети.

## Порядок выполнения и оценка трудоёмкости
